## Ejecución de las pruebas SQL (2026-11-08)
- **Entorno:** SQL Server Express local (`localhost\SQLEXPRESS`), base `EventCR_BoleteriaPro_DB` instalada con todos los módulos.
- **Resultado:** 14 de 14 pruebas en OK: registrar pago, aprobar con emisión de entradas, entradas válidas con código único y SHA-256, nominación que regenera el hash, registrar ingreso, rechazar con motivo, comprobante duplicado, monto insuficiente, solo auditores aprueban, pago validado no se reprocesa, solo validadores registran ingresos, código inexistente, doble ingreso y entradas emitidas = unidades pagadas.
- **Sin efectos en los datos:** los conteos y checksums de `Pedidos` y `Entradas` fueron iguales antes y después de la ejecución.
- **Corrección al script:** se agregó `IF @@TRANCOUNT > 0 ROLLBACK TRANSACTION;` en los `CATCH` de las pruebas finales. Sin eso, el error lanzado dentro de la transacción de `sp_Pago_Aprobar` (que usa `XACT_ABORT ON`) dejaba una transacción no confirmable abierta, y las pruebas "código inexistente" y "doble ingreso" fallaban con el error 3930 antes de evaluar su caso. Los procedimientos almacenados no cambiaron.
- **Requisito:** el script necesita al menos un usuario `AuditorPagos` y uno `ValidadorAcceso` activos (si no, las pruebas de ingreso fallan por permisos).

## Ejecución de la prueba de integración (2026-11-08)
- **Prueba:** `Doble_ingreso_simultaneo_solo_uno_es_autorizado`, con `EVENTCR_PRUEBAS_SQL` apuntando a la misma base local.

- **Requisito:** la prueba usa como validador el usuario con `UsuarioId = 4` (`acceso@boleteriapro.cr`), que debe estar activo.
